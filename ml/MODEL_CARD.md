# Model card: `fertilizer-classifier-0.1.0`

Every number below is pulled from `ml/src/models/model_registry/registry.json`'s
`fertilizer-classifier`/`0.1.0` entry, from `ml/PROGRESS.md`'s dated entries for the same
run, or (Limitations section) from Richa's `docs/evaluation-report.md`, unless marked
`TODO(metric)`. Nothing here is estimated or rounded from memory. Written for S10
(`docs/prompt-packs/saloni.md`); the ML standards this follows are
`~/claude-plugins/ml-ds-standards/CLAUDE.md` section 5.

## Intended use

Refines **which fertilizer product** (of five options in its training target: `urea`, `dap`,
`np_28_28_0`, `np_20_20_0`, `npk_17_17_17` -- only the first three currently have a verified
price in `fertilizer_products.csv`; `np_20_20_0` and `npk_17_17_17` are valid classifier
outputs that are *also* currently unpriced, see "Risk and cost" below for how an unpriced
product is still recommended) is the best fit for a soil-test-based fertilizer plan for one of seven Punjab field
crops (wheat, rice, maize, cotton, sugarcane, barley, chickpea). It is one
input among several, not the source of the plan: **the rule-based dose formula
(`ml/src/engine/npk_calculator.py`) sets quantity, timing and the schedule regardless of what
this model says** — see "Decision policy" below. If the classifier's top prediction disagrees
with the formula's own product choice, the formula wins and the disagreement is recorded in
`explanation.data_notes`, never silently dropped.

## Out-of-scope uses

- **Not a standalone dose recommender.** It never outputs a quantity, a date, or an
  application schedule — those come from `npk_calculator.py` regardless of this model's
  existence or accuracy (`recommendation_engine.py`'s own module docstring: "the classifier is
  optional, not a hard requirement").
- **Not validated on real farmer data.** Every training, validation and test row is
  synthetic (see "Training data" below). It has never been evaluated against an actual
  farmer's logged outcome.
- **Not regional beyond Punjab.** Every reference dose behind both the formula and this
  model's own features is a PAU (Punjab Agricultural University) Package of Practices
  number. Using this for a different state's agro-climatic zone would silently apply the
  wrong standard dose.
- **Not for crops outside its trained set** (the seven above), and **never predicts** `mop`,
  `ssp` or `npk_14_35_14` at all -- those three are entirely the rule-based layer's domain
  (DAP/MOP/urea product-mapping in `to_products()`), never a classifier output. `np_20_20_0`
  and `npk_17_17_17` *are* in scope for the classifier despite currently having no verified
  price (see "Intended use" above and "Risk and cost" below for the general unpriced-product
  policy).
- **Not a safety-critical or financial system.** This is a Smart India Hackathon prototype.
  It has not been reviewed by an agronomist for real-world deployment (see "Limitations" and
  the standing caveat repeated throughout `ml/PROGRESS.md`).

## Training data

- **Say plainly: this classification data is entirely synthetic, and it is small at the
  per-class level.** 2,800 rows total. **Every single row's `data_source` is `synthetic`** --
  there are zero real rows in this dataset as currently built (`data/processed/train.csv`,

- **Versions/hashes:** dataset content hash `9eb97903` (registry `dataset_hash`), config hash
  `626c8a31` (registry `config_hash`, of `configs/train.yaml` at training time), git commit
  `f234d21` (registry `git_sha` -- the commit that produced this exact artifact, not the
  current branch tip).
- **Date:** trained `2026-09-27T13:24:19Z` (registry `date`; run record
  `models_artifacts/runs/20260927T132419Z/`, gitignored/untracked like all run artifacts).
- **Size and split:** seeded (42), stratified 70/15/15 -- **train 1,958 / val 421 / test 421**
  rows (`dataset_manifest.json`'s `train_dataset_version.split_sizes`). Evenly balanced across

  here rather than silently repeated). Whether present at 0 or 2 rows, the reasoning holds:
  too few to place in every CV fold, let alone learn; the rule-based

- **Features (`FEATURE_COLUMNS`, `feature_engineering.py`):** `crop_id`, `variety_id`, `n`,
  `p`, `k`, `temperature_c`, `humidity_pct`, `moisture_pct`. N/P/K are real kg/ha for every
  synthetic row and every live request; they are deliberately `NaN` for the real 99-row
  dataset's rows specifically (not present in this training run at all, since it's 100%
  synthetic) because their unit was found empirically inconsistent with kg/ha, not merely
  unstated.
- **Known biases, from earlier real-data analysis (`ml/data/EDA_FINDINGS.md`) -- caveat, not
  a direct finding about this data:** that document analyzed the tiny original 50-row real
  dataset, not the 2,800-row synthetic dataset this model is actually trained on. Its
  findings (near-total `temperature_c`/`humidity_pct` collinearity, `soil_type` redundant
  with `crop_id`, a possible train/test near-duplicate leakage risk) informed the original
  model-family choice (favor regularized/low-variance models, compare against baselines) but
  **have not been re-verified against the synthetic data specifically** -- `TODO(metric)`:
  a fresh collinearity/leakage pass on the actual 2,800-row synthetic set would strengthen
  this section.
- **Known bias, verified directly in this data:** severe class imbalance (`urea` at 47.8%,
  `npk_17_17_17` at 0.6%) is real and drives every metric choice below (macro-F1/balanced
  accuracy over raw accuracy, `class_weight=balanced_subsample`).

## Evaluation protocol

- **Cross-validation:** 5-fold `StratifiedKFold`, seed 42, on train+val combined (2,379 rows)
  -- combining is deliberate: at this dataset size, cross-validation is the primary evidence,
  not a single frozen split (same reasoning Richa's `EDA_FINDINGS.md` gave for the original
  smaller dataset, carried forward).
- **16-candidate, 2-baseline model comparison** across model families (dummy baselines,
  logistic regression, 3 XGBoost variants, `random_forest` x3, `extra_trees`,
  `gradient_boosting`, `hist_gradient_boosting`, `knn`, `linear_svm`, `gaussian_nb`) under
  identical CV methodology -- full table in `ml/PROGRESS.md`'s model-comparison entries.
  `random_forest` (150 estimators, max_depth 6, `class_weight=balanced_subsample`) won on
  macro-F1 and MCC without the sharp accuracy-vs-fairness trade-off the linear/probabilistic
  candidates made trying to handle the same imbalance.
- **Baseline gate (`beats_baseline()`):** the candidate must beat the strongest of the dummy
  baselines (majority-class, stratified-random) **and** `logistic_regression` (the
  ml-ds-standards "simple model" baseline) by more than one fold-noise unit (candidate's
  mean-std > baseline's mean+std on macro-F1). This gate previously only checked the dummy
  baselines; fixed in a later review pass (see `ml/PROGRESS.md`'s external-review entry) --
  `random_forest` does clear it against `logistic_regression` too (0.370 mean-std vs 0.311
  mean+std).
- **Frozen test split, evaluated exactly once:** 421 rows, never touched before or since that
  one `--final-test` run. `evaluate_classifier` (Richa's, contract C7) computes point
  estimates, a 1,000-resample bootstrap 95% CI (seed 42), per-class precision/recall/F1, a
  confusion matrix, and (added in a later pass, same frozen predictions, verified to reproduce
  the exact same point estimates before being added -- never a second look at the test split)
  a per-crop breakdown via `per_slice()`.

## Decision policy

The model **never** sets quantity, timing, or the schedule. Per contract C1/C6
(`docs/api-contract.md`, `npk_calculator.py`):

```
fertilizer needed = standard dose (PAU) + soil-test adjustment (ICAR-IISS) - prior credit
```

computed independently of this classifier, per nutrient (N, P2O5, K2O), via a reference-dose
lookup or an STCR equation where one exists. `to_products()` then maps nutrient needs to
specific products (DAP for P, MOP for K, urea for remaining N) using this same rule-based
logic. **The classifier only ever refines which product name is shown as the primary
recommendation when its top prediction and the rule-based choice agree**; when they disagree,
the rule-based choice is kept, and the disagreement is written into
`explanation.data_notes`/`rule_trace` as a `classifier_disagreement` entry -- visible, never
silently dropped. A missing or unregistered classifier degrades `/health` but never blocks
`/recommend` (`recommendation_engine.py`'s own module docstring documents this as a
deliberate design deviation from the literal S6 spec).

## Risk and cost

- **Risk** (`src/degradation/risk_analyzer.py`, Richa's): `assess_recommendation()` compares
  the farmer's logged previous usage against the computed nutrient need per nutrient, flags
  `over_application_ratio_medium`/`_high` or `under_application_ratio`
  (`agronomy_rules.yaml` thresholds) and returns a level (`low`/`medium`/`high`) with a
  plain-language soil-health and yield-impact sentence. `score_planned()` does the same for a
  farmer's own planned (not-yet-applied) dose, via `POST /risk-score`.
- **Cost** (`src/engine/cost.py`, mine): `estimate_cost` sums `quantity_kg_per_acre x
  price_inr_per_kg` over the priced schedule lines; `compare_to_history` compares that against
  the farmer's logged previous cost in the same crop-season window
  (`feature_engineering.season_length_days()`, falling back to `credit_window_days` with an
  explicit warning where no sourced season length exists yet). A product with no verified
  price (currently `ssp`, `npk_14_35_14`, `npk_17_17_17`, `np_20_20_0` -- `mop` was resolved
  2026-09-27, see below) is still recommended with a real dose -- it's excluded from the cost
  breakdown, never priced at zero or guessed, with a `data_notes` entry saying why (see
  `ml/PROGRESS.md`'s 2026-09-27 MOP-policy entry).

## Limitations and failure modes

`docs/evaluation-report.md` (R12, Richa's, added 2026-09-27) is now the authoritative
failure-mode analysis; summarized here, not duplicated in full:

- **Never evaluated on real data at meaningful scale.** The test split has 421 rows, of which
  only 10 are real (97.6% synthetic across train/val/test, 57 real rows total from the 99-row
  public Kaggle dataset after dropping unusable rows/classes). Every accuracy number in this
  card is an upper bound on real-world performance, not an estimate of it.
- **Severe class imbalance** means `npk_17_17_17` (3 test rows, recall 0.667 but on a base too
  thin to trust) and `np_20_20_0` (recall 0.167) are the least trustworthy predictions the
  model makes. `dap` has perfect recall (1.000) but only 40.4% precision -- a lot of other rows
  get misclassified *into* dap. `urea`, the largest class, is the most reliably identified
  (recall 0.716, F1 0.729).
- **Chickpea collapses to "dap" entirely**, not a subtle confusion: every one of chickpea's 42
  misclassified test rows (both true `np_20_20_0` and true `np_28_28_0`) was predicted `dap`,
  regardless of the row's actual N/P/K values -- likely because chickpea's low-N reference dose
  (14.8 kg/ha vs wheat's 123.6, it being a legume) looks close enough to dap's typical low-N
  profile that the model never learned to separate them within that crop. Per-crop macro-F1 is
  lowest for barley (0.139) and wheat (0.140), then chickpea (0.181) -- chickpea's classifier
  output specifically should not be trusted (the dose calculator's own numbers, unaffected, are
  still the source of truth regardless).
- **`np_28_28_0` <-> `urea` is the single largest cross-crop confusion pattern** in both
  directions -- reflects genuine label ambiguity in the synthetic generator's mid-range soil
  sampling, not an implausible model failure.
- **Region ambiguity risk, structural not yet triggered:** `reference_doses.csv`/
  `stcr_equations.csv` carry a `region` column the dose formula doesn't yet use to
  disambiguate (harmless today -- every crop/variety/irrigation combination has exactly one
  region -- but `npk_calculator.py` now raises rather than silently guessing if that ever
  changes; see `ml/PROGRESS.md`'s external-review entry).
- **The formula itself checks out independently:** a separate 63-check grid Richa ran directly
  against `compute_balance()`'s live output found zero arithmetic mismatches -- every one of the
  9 "violators" was the same already-disclosed data gap (no sourced soil-adjustment row yet for
  wheat/N, wheat/P, rice/N), not a formula bug.
- **MOP's price is now resolved** (2026-09-27, PIB Release ID 2237470, ₹34.21/kg) --
  `ssp`, `npk_14_35_14`, `npk_17_17_17` and `np_20_20_0` remain unpriced (see "Risk and cost").
- **The registered v0.1.0 model predates this merge's data fixes** (barley's
  `split_schedule.csv` row, sourced P/K nutrient efficiency). A fresh local reproduction on the
  current dataset shows a 6th class (`npk_14_35_14`, 9 rows) not present when v0.1.0 was
  registered, and correspondingly different metrics (macro F1 0.341 vs the registered 0.469).
  The reproduction is exact and repeatable (not a fluke), but whether to register a new model
  version over this is an open decision, not yet made -- see `ml/PROGRESS.md`.

## Fairness and regional caveats

- **Region:** every standard dose is PAU (Punjab). This model and the formula behind it have
  no signal at all for any other Indian state's agro-climatic zone; deploying against
  non-Punjab soil-test data would silently apply the wrong standard dose with no warning, since
  the region field isn't currently threaded through the request at all (see "Limitations").
- **Crop coverage:** seven crops, evenly represented in training (400 rows each) -- but
  real-world Punjab cropping patterns are not evenly split this way (wheat and rice dominate
  actual sown area). The model has not been reweighted or evaluated against real crop
  prevalence.
- **Language/accessibility:** out of scope for this model card -- the classifier has no
  language dependency; see the frontend brief for Hindi/English handling.
- **Variety coverage:** only `rice/pr_132`, `chickpea/kabuli` and `wheat/wh_542` (the last not
  yet in `crop_varieties.csv` -- flagged for Richa) have variety-specific reference doses.
  Every other variety request falls back to the crop's generic dose.

## Ownership and retraining plan

- **Owner:** Saloni (`ml/src/api/`, `ml/src/engine/`, `ml/src/models/`) -- ML/ML-core, this
  repo's `AGENTS.md`.
- **Retrain when:** the reference tables change materially (a new crop/variety dose, a
  corrected soil-adjustment value), the synthetic dataset is regenerated, or real Kaggle
  labels ever become available (at which point the whole synthetic-as-raw-data policy in
  `ml/PROGRESS.md` should be revisited, not just the model).
- **How:** `python -m src.models.train --config configs/train.yaml` (CV comparison only) or
  `--final-test` once a candidate is chosen and ready for its one, permanent frozen-test-split
  evaluation. Never rerun `--final-test` for a version that already has `test_metrics` --
  `_next_version()` will make a new version number automatically rather than refuse outright,
  so re-running casually is a real way to accidentally touch the test split again; only do it
  deliberately, once, per version.
- **Monitoring:** not yet built. `TODO`: a production deployment would need drift detection on
  the incoming feature distribution (crop/soil-test values) and periodic re-evaluation against
  any real logged outcomes once they exist -- out of scope for this hackathon prototype.
